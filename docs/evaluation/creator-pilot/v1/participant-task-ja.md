# 参加者向け課題シート（日本語）

このシートは、SynapseGitで最初の制作記録を残す一連の操作を、あなた自身の手で一度
たどってもらうためのものです。正解・不正解を測る試験ではありません。分からないこと、
迷ったこと、使いにくいと感じたことは、遠慮なく進行役に伝えてください。

## 0. 事前準備

- **対象version**: v0.9.0。
- **必要なbinaryは3つ**です。
  - `synapse` — コマンドラインから記録・確認するためのbinary。
  - `synapse-local` — ブラウザ画面（localhost限定）から操作するためのbinary。
  - `synapse-present` — 記録した内容を、外部に見せるための読み取り専用bundleへ書き出すbinary。
  - install手順は進行役が事前に準備します。自分でinstallする場合は
    [Installation guide](../../../install.md)に従ってください。
- **前提条件**:
  - ターミナルを一つ開いて操作できること（`synapse` / `synapse-local`の実行）。
  - ブラウザで`http://127.0.0.1:...`のような自分のPC上のアドレス（localhost）を開けること。
  - **画面は日本語のみです。** 英語話者の場合、画面の読み取りに進行役の補助が必要になることが
    あります（英語UIは別Issueで開発中で、まだこのversionには含まれていません）。
- **今回使う3つの画像の役割**（練習用のsynthetic=作りものの画像です。実在の壁画ではありません）:
  1. **Original** — 損傷が目立つ前の参照状態。
  2. **Current** — 亀裂・剥落・変色などが見える現在の観測状態。
  3. **AI output（AI-attributed proposal）** — 修復案として用意された3枚目の画像。
     **SynapseGitはこの画像をモデルで生成しません。誰か（今回は進行役があらかじめ用意した画像）が
     用意したファイルを、「AIが用意した案」として記録するだけです。**
- **自分の画像に置き換える場合の準備**（このシートの課題自体は練習用画像で行い、後で試す場合の
  参考にしてください）:
  - 3枚とも自分が権利・利用許可を持つ画像を用意してください。
  - Original／Currentは同じ対象の異なる時点の状態、AI outputは案として比べたい3枚目の画像、
    という3枚構成にします。
  - SynapseGitは画像の中身ではなく、ファイルの**bytesそのもの**を記録・比較します。
    見た目を加工しても、bytesが変わっていれば「違うファイル」として記録されます。
  - 各ファイルは64 MiB以下、3ファイル合計192 MiB以下にしてください（localhost画面の場合）。

## 1. 画像をimportし、AI outputを比べる

進行役から、**CLI（ターミナル）**と**ブラウザ画面（localhost UI）**のどちらで課題を行うか
指示されます。どちらも最終的に同じ内容を記録します。

### 1-A. CLIで行う場合

練習用repositoryのpathとsession名を進行役に確認してから、次のREPO・SESSION・ORIGINAL・
CURRENT・AI_OUTPUT・SUBJECT・CREATOR・DECISION・RATIONALEを実際の値に置き換えて実行します。

```bash
synapse creator-run REPO SESSION \
  ORIGINAL CURRENT AI_OUTPUT \
  --subject "SUBJECT" \
  --creator "CREATOR" \
  --decision DECISION \
  --rationale "RATIONALE"
```

DECISIONには`adopt`／`reject`／`defer`のいずれか一つを入れます。

- `--decision`にはこの後の課題2で決めた判断（`adopt`／`reject`／`defer`のいずれか一つ）を入れます。
- 実行後、直後に出力される内容を確認してください。

### 1-B. ブラウザ画面（localhost UI）で行う場合

進行役が起動した`synapse-local`のプロジェクト画面を開きます（進行役から渡された
`http://127.0.0.1:...`のURLを使ってください）。

1. プロジェクト画面で新しいセッションを開始し、session名・表示名を入力します。
2. Original／Current／AI output（AI-attributed proposal）の3画像を、それぞれの指定欄で選びます。
   画像を選んだだけでは送信されません。
3. 内容を確認してからProposalを作成（送信）します。
4. セッション画面の「画像を拡大して比較」を開き、比較したい2画像（例: CurrentとAI output）を
   選びます。「重ねて表示」は、選んだ2画像のdecode後の幅と高さが一致する場合だけ選べます。
   選べる場合は不透明度を変えて重ねて見られます（位置合わせや自動差分ではなく、同じ左上原点で
   重ねて見るだけの機能です）。一致しない場合は「並べて表示」だけになります。
5. 続けて課題2の判断（Adopt／Reject／Defer）と理由をこの画面で入力します。ボタンを押すと
   **ブラウザの確認ポップアップ（`確認`／`キャンセル`）が表示されます。** 内容を読んでから
   「確認（OK）」を選ぶと記録され、「キャンセル」を選ぶと何も記録されず入力した理由もそのまま
   残ります。

## 2. Adopt／Reject／Deferのいずれかを、理由付きで判断する

課題1を実行する前に、次の3つの選択肢の説明を読み、どれを選ぶか自分で決めてください。

- **Adopt** — 用意されたAI outputをそのまま選ぶ。
- **Reject** — AI outputを選ばず、Current（現在の状態）をそのまま維持する。
- **Defer** — 採否の判断を保留する。Current（現在の状態）は維持されるが、
  「保留した」という記録が残る。

決めたら、その理由を短い文章（`--rationale`、またはブラウザ画面の理由欄）で書いてください。
理由は自由記述で構いません。

**この判断は一度確定すると、同じセッションでは変更・再編集できません。** Deferを選んでも
「後で必ず思い出せる仮の状態」ではなく、そのセッションの判断としてはそこで完了します。

## 3. 記録した判断を読み返す

判断を記録したら、記録された内容を読み返します。CLIで行った場合は次を実行します
（REPO・SESSIONは課題1-Aで使った値と同じです）。

```bash
synapse creator-report REPO SESSION
```

出力の中から次を確認してください。

- `disposition=` に、自分が選んだ判断（adopt／reject／defer）が表示されているか。
- `selected=` の値（adoptのときだけ`true`になります）。
- `byte_identity=` の値（`identical`か`different`か）。
- 自分が入力した理由（rationale）が、記録どおりに表示されているか。

ブラウザ画面（localhost UI）で行った場合は、完了したセッション画面の「記録した判断」欄で
同じ内容（判断・理由）を確認してください。進行役の指示があれば、CLIの`creator-report`と
画面の表示を見比べてください。

## 3b. 公開用の文章がどこから作られるかを、公開せずに確認する

他の人に見せる文章がどこで用意されるかを見る課題です。**ここでは何も外部へ公開しません。
ローカルで画面やfileを見るだけです。**

- **ブラウザ画面で行う場合**: プロジェクト画面の「公開用の制作ノートを作る」を開きます。
  課題1で完了させたセッションを選び、画面を開いた時点で各入力欄に何が入っているかを
  記録してください。formは送信しないでください。
- **CLIで補足する場合（任意）**: 進行役から指定された、まだ存在しない出力先pathを`OUT`として、
  次を実行します。

  ```bash
  synapse-present export REPO OUT --session SESSION --public
  ```

  生成された`OUT`配下のfile（`index.html`、`story.md`、`projection.json`など）を開き、
  自分が入力したrationaleの文章を探して、見つかったことを記録してください。

この課題の結果は、次の理解度確認の質問4に使います。

## 4.（任意）別セッションで次の候補を試す

時間があれば、進行役の指示に従って**別のsession**（同じ画像でも新しいAI output画像でも
構いません）で、もう一度課題1〜3を行ってみてください。**すでに使ったsession名は再利用できません。**
新しいセッションは新しいsession名で作成してください。

## 課題が終わったら

進行役が用意した理解度確認の質問（`comprehension-questions-ja.md`）に、自分の言葉で
答えてください。正解を調べ直す必要はありません。分からなければ「分からない」と書いて
構いません。
