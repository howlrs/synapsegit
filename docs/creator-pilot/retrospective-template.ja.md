# 実制作 Pilot 振り返り・継続判断テンプレート

このテンプレートは、[実制作 Pilot 開始前チェックリスト](./start-checklist.ja.md)で始めた
一つのPilotの終了時に使います。観測した事実、本人の意見、続けるかの判断を別々に記録します。
一回のPilotの結果だけで、creator benefitが実証されたとは主張しません。

- **復元確認:** `[実施日・archive・空の復元先・creator-reportを読めたsession／未実施と理由]`

## 2. 観測値

ここには、session、command出力、時計、または事前に定めた手順から確認できる値だけを書きます。
推測、感想、継続判断は次の節へ書きます。

### session と判断の内訳

| 観測項目 | 値 | 確認方法・範囲 |
|---|---|---|
| 完了session数 | `[ ]` | `[session名またはcreator-report]` |
| Adopt | `[ ]` | `[session名]` |
| Reject | `[ ]` | `[session名]` |
| Defer | `[ ]` | `[session名]` |
| 未完了または記録しなかった節目 | `[ ]` | `[理由]` |

`Adopt`、`Reject`、`Defer`は価値の順位や成功率ではありません。合計が完了session数と一致しない場合は、
sessionの範囲または数え方を記します。

### Stage 0 の Pilot metric

Stage 0のmetricを、v0.10.0の実装だけから自動的に得られるかで分けます。手計時や本人による
説明確認は可能でも、SynapseGitが測定・保証した値ではありません。その場合は測定者、手順、対象を併記し、
実施しなければ **未測定** と書きます。

| 仮説とmetric | v0.10.0での扱い | 観測値 | 観測方法・条件 |
|---|---|---|---|
| 記録が制作を中断しない: Captureの能動入力中央値20秒以内 | **未測定**。Capture機能と入力時間計測は未実装 | `未測定` | `[ ]` |
| 節目を残す負担が小さい: Commitの能動入力中央値30秒以内 | **未測定**。Commit入力時間の計測は未実装 | `未測定` | `[ ]` |
| 判断根拠を再発見できる: 1か月後に重要変更を本人が2分以内に説明 | **観測可能・手動**。`creator-report`で判断の記録は再読できるが、説明時間や理解を自動計測しない | `[未測定／値]` | `[実施日、対象session、説明者、計時方法]` |
| 引継ぎと報告が速くなる: report/handoff作成時間を現行手順と比較 | **観測可能・手動**。`creator-report`は作成できるが、handoffと現行手順との比較は自動計測しない | `[未測定／値]` | `[比較対象、計時方法、同じ範囲か]` |
| 却下案も再利用できる: proposal再利用件数と再探索時間 | **観測可能・手動**。記録済みproposalの派生・再レビューは使えるが、再利用価値と探索時間は自動計測しない | `[未測定／値]` | `[元session、再利用session、計時方法]` |
| archiveがservice外で生きる: 空store restore成功率100% | **観測可能・手動**。`export`、空のrestore先、`creator-report`で確認できるが、成功率を自動集計しない | `[未測定／成功回数 ÷ 試行回数]` | `[archive、復元先が空だった確認、report確認]` |

「観測可能・手動」の値は、製品のbenchmarkや一般化できる成功率ではありません。1回だけの復元なら、
`1 ÷ 1` と記録し、100%という品質保証にはしません。

## 4. 継続判断

一つ選び、観測値と本人の意見を根拠として記します。判断はこのPilotと記した範囲に限ります。

- [ ] **続ける** — 同じSubject・節目・保存方法で次の期間も続ける。
- [ ] **範囲を変えて続ける** — Subject、節目、期間、保存方法、または記録担当を変える。
- [ ] **やめる** — このPilotを終了する。
