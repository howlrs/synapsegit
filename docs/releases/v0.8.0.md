# SynapseGit v0.8.0 — Stage 0 preview

`v0.8.0` is a preview release on top of `v0.7.0`. It brings the localhost
Creator workflow that was developed after v0.7.0 into the packaged three-binary
release: archive export and empty-target restore controls, import preflight,
manual image comparison, explicit decision review, private Creator notes and
pins, derived candidates, and the public-text sidecar form. The Core v0.1
protocol, `sg-oid-v1`, directory archive format, and three-binary distribution
remain unchanged. This is a source-available evaluation release, not a
production or hosted service.

## Highlights

- Project pages expose the existing authenticated bounded archive export and
  restore APIs when `--archive-root` is configured. Export requires a new
  logical archive slug and exact project-key confirmation. Restore is fixed to
  the open registered project only when its displayed Refs and reflog are
  empty, and requires a listed slug, typed key, empty-target confirmation, and
  browser confirmation. Both use process-local queued jobs; successful restore
  keeps the source/restored Creator-report equivalence reminder visible.
- Creator import now previews selected displayable raster files locally, shows
  file sizes and UTF-8 byte limits, permits clearing an individual selection,
  and locks inputs during submission. Selection and previewing do not upload a
  file. Unsupported or corrupt previews remain importable under the existing
  opaque-file contract.
- Pending and completed Creator sessions offer a read-only manual comparison
  dialog for two decoded images with fit, 100%, and 200% views. It performs no
  image registration or difference analysis.
- Decision review explains the Adopt/Reject/Defer outcome before confirmation,
  reports rationale byte limits while typing, locks its inputs during
  submission, and renders the recorded rationale as escaped multiline text.
  Defer completes a session and does not reopen it.
- A Creator session can retain optional private, user-declared generation notes
  and up to ten private image-bound decision pins. Complete sessions can reuse
  their verified Original/Current bytes for a fresh candidate in the same
  project, with fresh identities and Human review. Archive/restore retains the
  private lineage.
- The localhost public-text form validates fresh author-supplied text for one
  complete non-derived session and downloads `presentation.toml`. Frozen
  publication v1 refuses derived sessions, including all-session export
  containing a complete derived session, because it cannot represent reused
  reference images without misrepresenting Current as a new observation.

## Install on Linux x86-64 GNU

The prebuilt archive is produced on Ubuntu 22.04 and requires glibc 2.34 or
newer. Other supported Unix-like hosts can build from the fixed tag with Rust
1.88 or newer.

```bash
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.8.0/synapsegit-v0.8.0-x86_64-unknown-linux-gnu.tar.gz
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.8.0/SHA256SUMS
sha256sum --check SHA256SUMS

gh attestation verify synapsegit-v0.8.0-x86_64-unknown-linux-gnu.tar.gz \
  --repo howlrs/synapsegit \
  --signer-workflow howlrs/synapsegit/.github/workflows/release.yml \
  --source-ref refs/tags/v0.8.0 \
  --deny-self-hosted-runners
```

Stop if either verification command fails. Do not extract or install an
unverified archive.

```bash
tar -xzf synapsegit-v0.8.0-x86_64-unknown-linux-gnu.tar.gz

mkdir -p "$HOME/.local/bin"
install -m 0755 synapsegit-v0.8.0-x86_64-unknown-linux-gnu/synapse "$HOME/.local/bin/synapse"
install -m 0755 synapsegit-v0.8.0-x86_64-unknown-linux-gnu/synapse-local "$HOME/.local/bin/synapse-local"
install -m 0755 synapsegit-v0.8.0-x86_64-unknown-linux-gnu/synapse-present "$HOME/.local/bin/synapse-present"
export PATH="$HOME/.local/bin:$PATH"

synapse --version
synapse-local --version
synapse-present --version
```

All three binaries should report `0.8.0`. See the
[installation guide](https://github.com/howlrs/synapsegit/blob/v0.8.0/docs/install.md)
for source installation and update precautions.

## Compatibility and migration

- Repositories created with v0.7.x require no planned format migration. Core
  v0.1 objects, `sg-oid-v1`, and directory archive semantics are unchanged.
- Archive browser controls are additive clients of the existing authenticated
  APIs. They remain unavailable unless `--archive-root` is configured, have no
  path or dynamic-target selector, and do not resume, clean up, or rewrite
  history after a failure or restart.
- Creator private notes, pins, and fixed source lineage are retained by normal
  Core archive/restore. They are private data and are not copied into the
  public-text form or publication bundles.
- Derived Creator sessions are intentionally refused by frozen publication v1.
  Select a complete non-derived session with `--session` for a v1 export.

Stage 0 APIs and formats do not yet carry a stable compatibility promise.
Export important repositories with the old binary before updating so that a
known-good recovery copy remains available.

## Known limits

- The archive, image comparison, and Creator controls are localhost features;
  they do not provide a public, multi-user, or production service.
- Credentials, review authority, and maintenance jobs remain process-local.
  Recovery requires fresh authentication and never reconstructs prior
  authority.
- Image comparison is manual viewing only. Capture tooling, pixel registration,
  visual-difference analysis, and physical-change interpretation are not
  implemented.
- Generic-artifact support remains source-library-only. There is no
  generic-artifact HTTP, CLI, browser, or remote-publication surface.
- The prebuilt artifact is Linux x86_64 GNU only. No crates.io, GHCR, Windows,
  macOS, or Linux ARM64 package is published.
