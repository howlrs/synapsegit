# SynapseGit v0.5.0 — Stage 0 preview

`v0.5.0` is the fifth tagged SynapseGit preview. It strengthens canonical
timestamp validation in publication bundle verification, unifies the I/O
error shape across `synapse-core`, `synapse-cas`, `synapse-publication`,
`synapse-creator`, and the `synapse` CLI, and single-sources portable-path
syntax validation with an explicit Windows drive-letter rule for publication
bundle paths. Machine-readable error codes are unchanged throughout. The Core
v0.1 protocol, `sg-oid-v1`, directory archive, and existing command surfaces
have no intentional format change. This remains a source-available evaluation
release, not a production or hosted service.

## Highlights

- Publication bundle verification now validates canonical timestamps against
  the proleptic Gregorian calendar instead of only the lexical wire form, so
  calendar-invalid values such as month 13 or February 30th are rejected.
  Canonical timestamp parsing is single-sourced in `synapse-canonical`, which
  `synapse-schema` and `synapse-core` now also delegate to.
- `synapse-creator` and the `synapse` CLI report I/O failures with the same
  `Io { operation, path, source }` shape already used by `synapse-core`,
  `synapse-cas`, and `synapse-publication`, so failures from creator sessions
  and CLI commands carry richer operation context. Machine-readable error
  codes are unchanged. This adds a field to the public `CreatorError::Io`
  struct variant, which is a source-level shape change for any downstream
  code that destructures it without `..`; see
  [Compatibility and migration](#compatibility-and-migration).
- Portable-path syntax validation (rejecting a leading `/`, a `\` byte, a
  `.`/`..`/empty path segment, and a NUL byte) is single-sourced in
  `synapse-canonical`, which `synapse-artifact`, `synapse-publication`,
  `synapse-cas`, and `synapse-schema` all now delegate to. Publication bundle
  path validation also explicitly rejects an ASCII Windows drive-letter
  prefix (for example `C:`) as a named rule; such paths were already
  rejected end to end by an unrelated fixed-character-set check, so no
  previously accepted path becomes rejected. A NUL-byte bundle path is still
  rejected, but now reports the explicit unsafe-path message instead of the
  unrelated fixed-character-set message it reported before. Machine-readable
  error codes are unchanged in both cases.
- The pre-1.0 policy of keeping public Rust error enums exhaustive (no new
  `#[non_exhaustive]`) is now documented in `CONTRIBUTING.md`.

## Install on Linux x86-64 GNU

The prebuilt archive is produced on Ubuntu 22.04 and requires glibc 2.34 or
newer. Other supported Unix-like hosts can build from the fixed tag with Rust
1.88 or newer.

```bash
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.5.0/synapsegit-v0.5.0-x86_64-unknown-linux-gnu.tar.gz
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.5.0/SHA256SUMS
sha256sum --check SHA256SUMS

gh attestation verify synapsegit-v0.5.0-x86_64-unknown-linux-gnu.tar.gz \
  --repo howlrs/synapsegit \
  --signer-workflow howlrs/synapsegit/.github/workflows/release.yml \
  --source-ref refs/tags/v0.5.0 \
  --deny-self-hosted-runners
```

Stop if either verification command fails. Do not extract or install an
unverified archive.

```bash
tar -xzf synapsegit-v0.5.0-x86_64-unknown-linux-gnu.tar.gz

mkdir -p "$HOME/.local/bin"
install -m 0755 synapsegit-v0.5.0-x86_64-unknown-linux-gnu/synapse "$HOME/.local/bin/synapse"
install -m 0755 synapsegit-v0.5.0-x86_64-unknown-linux-gnu/synapse-local "$HOME/.local/bin/synapse-local"
install -m 0755 synapsegit-v0.5.0-x86_64-unknown-linux-gnu/synapse-present "$HOME/.local/bin/synapse-present"
export PATH="$HOME/.local/bin:$PATH"

synapse --version
synapse-local --version
synapse-present --version
```

All three binaries should report `0.5.0`. See the
[installation guide](https://github.com/howlrs/synapsegit/blob/v0.5.0/docs/install.md)
for source installation and update precautions.

## Compatibility and migration

- Repositories created with v0.4.0 require no planned format migration. Core
  v0.1 objects, `sg-oid-v1`, and directory archive semantics are unchanged.
- `synapse-creator`'s public `CreatorError::Io` struct variant gains an
  `operation: &'static str` field (`synapse-cli`'s internal `CliError::Io`
  changes the same way, but that type is not public). This is a source-level
  shape change: downstream code that pattern-matches `Io { path, source }`
  without `..`, or constructs the variant directly, needs to add the new
  field. Per `CONTRIBUTING.md`, public Rust error enum *shape* is not a
  stability contract before 1.0; the stable contract is the
  machine-readable error code, which this change does not touch. No enum
  gained or lost a variant, and no new `#[non_exhaustive]` was added.
- The publication-bundle NUL-byte-path rejection message changed (the error
  code did not); code that matches on that specific message text, rather
  than the error code, should be updated.

Stage 0 APIs and formats do not yet carry a stable compatibility promise.
Export important repositories with the old binary before updating so that a
known-good recovery copy remains available.

## Known limits

- Generic-artifact support remains source-library-only, unchanged since
  v0.4.0. There is no generic-artifact HTTP, CLI, browser, or remote
  publication surface.
- Credentials and approvals remain process-local. Recovery requires fresh
  authentication and authorization, and never reconstructs prior authority.
- Generic public bundles are unsigned local derived views, not proofs of
  authorship, truth, permission, completeness, or physical change.
- The existing browser and command surfaces remain image-workflow-oriented.
- The prebuilt artifact is Linux x86_64 GNU only. No crates.io, GHCR, Windows,
  macOS, or Linux ARM64 package is published.
