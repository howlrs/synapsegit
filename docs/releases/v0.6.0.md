# SynapseGit v0.6.0 — Stage 0 preview

`v0.6.0` is a preview release on top of `v0.5.1`. It adds a read-only,
bounded localhost archive listing to `synapse-local`, tightens
publication-comprehension scorer corpus validation, and fixes a
misclassified restore error code. The Core v0.1 protocol, `sg-oid-v1`,
directory archive format, and existing command surfaces are otherwise
unchanged. This remains a source-available evaluation release, not a
production or hosted service.

## Highlights

- localhost browser: a new read-only archive listing (`GET /archives` plus a
  server-rendered dashboard section), enabled by a new `--archive-root PATH`
  `synapse-local` startup flag. Listing bounded-scans the server-owned
  archive root's direct slug-named entries and reports each as `valid` (with
  its manifest checksum), `invalid`, or `staging_or_unknown`, from a
  manifest-level Core inspection that verifies the manifest checksum,
  structure, and per-object presence/length but does not read object
  content. Archive export and restore remain CLI-only; this is a read-only
  inspection surface only, reachable exclusively when an operator opts in
  with `--archive-root`.
- A checksum-verified archive manifest containing a structurally invalid
  object OID string is now reported as `archive_invalid` by restore
  (`Repository::restore_from` and the `synapse` CLI `restore` command)
  instead of `schema_invalid`, aligning it with
  `spec/core/v0.1/archive-profile.md`'s normative error-code mapping.
- `scripts/score_publication_comprehension.mjs` now validates
  `questionnaire.json`/`oracle.json`/`protocol.json` schema identity, that
  `protocol.json`'s `context.track_matrix` exactly matches the scorer's
  fixed evaluator-kind/track group order, that no question names a
  duplicate case or track, and that every case/track combination has at
  least one applicable question, all at corpus-load time. Oracle answer
  integers are now required to be safe integers (`Number.isSafeInteger`);
  response-side integer scoring is unchanged. Malformed inputs continue to
  fail via the existing `score_publication_comprehension_error:` stderr
  prefix and exit code 1 — no new machine-readable response error codes
  were introduced, and the frozen v1 corpus and score-report output are
  unaffected. `scripts/test_publication_comprehension_scorer.mjs` gained
  matching regression coverage.
- `crates/synapse-publication/examples/generate_evaluation_corpus.rs` now
  removes the output directory it created if generation fails partway
  through, instead of leaving a partial corpus behind. An existing output
  directory is still refused outright and is never touched by this cleanup.

## Install on Linux x86-64 GNU

The prebuilt archive is produced on Ubuntu 22.04 and requires glibc 2.34 or
newer. Other supported Unix-like hosts can build from the fixed tag with Rust
1.88 or newer.

```bash
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.6.0/synapsegit-v0.6.0-x86_64-unknown-linux-gnu.tar.gz
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.6.0/SHA256SUMS
sha256sum --check SHA256SUMS

gh attestation verify synapsegit-v0.6.0-x86_64-unknown-linux-gnu.tar.gz \
  --repo howlrs/synapsegit \
  --signer-workflow howlrs/synapsegit/.github/workflows/release.yml \
  --source-ref refs/tags/v0.6.0 \
  --deny-self-hosted-runners
```

Stop if either verification command fails. Do not extract or install an
unverified archive.

```bash
tar -xzf synapsegit-v0.6.0-x86_64-unknown-linux-gnu.tar.gz

mkdir -p "$HOME/.local/bin"
install -m 0755 synapsegit-v0.6.0-x86_64-unknown-linux-gnu/synapse "$HOME/.local/bin/synapse"
install -m 0755 synapsegit-v0.6.0-x86_64-unknown-linux-gnu/synapse-local "$HOME/.local/bin/synapse-local"
install -m 0755 synapsegit-v0.6.0-x86_64-unknown-linux-gnu/synapse-present "$HOME/.local/bin/synapse-present"
export PATH="$HOME/.local/bin:$PATH"

synapse --version
synapse-local --version
synapse-present --version
```

All three binaries should report `0.6.0`. See the
[installation guide](https://github.com/howlrs/synapsegit/blob/v0.6.0/docs/install.md)
for source installation and update precautions.

## Compatibility and migration

- Repositories created with v0.5.x require no planned format migration. Core
  v0.1 objects, `sg-oid-v1`, and directory archive semantics are unchanged.
- The new `GET /archives` listing and `--archive-root` flag are opt-in and
  additive: `synapse-local` started without `--archive-root` behaves as
  before. No existing route, flag, or response shape changed.
- The restore error-code fix changes only which error code is reported for
  an already-invalid input (a manifest naming a structurally malformed
  object OID): callers that previously received `schema_invalid` for this
  specific case now receive `archive_invalid`. No other restore behavior
  changed.
- No public Rust API shape changed for existing callers in this release.

Stage 0 APIs and formats do not yet carry a stable compatibility promise.
Export important repositories with the old binary before updating so that a
known-good recovery copy remains available.

## Known limits

- Generic-artifact support remains source-library-only, unchanged since
  v0.4.0. There is no generic-artifact HTTP, CLI, browser, or remote
  publication surface.
- The new archive listing is read-only and inspects manifest-level integrity
  only (checksum, structure, per-object presence/length); it does not read
  object content, and archive export and restore remain CLI-only.
- Credentials and approvals remain process-local. Recovery requires fresh
  authentication and authorization, and never reconstructs prior authority.
- Generic public bundles are unsigned local derived views, not proofs of
  authorship, truth, permission, completeness, or physical change.
- The existing browser and command surfaces remain image-workflow-oriented.
- The prebuilt artifact is Linux x86_64 GNU only. No crates.io, GHCR, Windows,
  macOS, or Linux ARM64 package is published.
