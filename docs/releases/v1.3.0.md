# SynapseGit v1.3.0

`v1.3.0` makes the optional generation note easier to complete in the
localhost application while preserving the frozen v1 Core formats, canonical
bytes, OIDs, schemas, Refs, archives, and Human Decision boundary.

## Changes since v1.2.0

- The import form and the derived-session form for a new AI output show the
  optional **Tool used** and **Generation model** fields together, without
  opening the collapsed note. Prompt and intent stay under **Prompt and intent
  (optional)**.
- The form explains that the generation model is the model that generated this
  AI output, that it may differ from the model of the AI agent you work with,
  and that anything unknown can be left blank instead of guessed. A tool-only
  note and a blank note both import as before.
- Recorded notes and the Inbox review form label the model field "Generation
  model" (生成モデル).
- The Creator workflow and AI agent guides describe the field meanings, why
  neither the model nor a "known / unknown" choice is required, and conditions
  for later work. The effect of this layout on how often the model is recorded
  has not been measured.

The `creator-generation-note-v1` format, its UTF-8 byte limits, CLI, Inbox,
and API input, archive and restore, and public bundles are unchanged. A
generation note remains a private, user-declared record; it does not prove
that a model ran, who the author is, or that a result can be reproduced.

## Install and verify

Download the archive and `SHA256SUMS` for this exact release. Verify the
checksum and GitHub build provenance before extracting. If either verification
fails, stop. Do not extract or install an unverified archive. Export important
repositories with the old binary before updating, and retain the old archive
until v1.3.0 verifies the data.

See the tag-fixed [installation guide](https://github.com/howlrs/synapsegit/blob/v1.3.0/docs/install.md),
[changelog](https://github.com/howlrs/synapsegit/blob/v1.3.0/CHANGELOG.md), and
[compatibility policy](https://github.com/howlrs/synapsegit/blob/v1.3.0/docs/compatibility.md).
