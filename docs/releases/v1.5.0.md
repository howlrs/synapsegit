# SynapseGit v1.5.0

`v1.5.0` adds `synapse repair` to put damaged objects back from a good copy,
keeps a repository working after a file manager opens its folders, and makes
`fsck` report all damage, while preserving the frozen v1 Core formats,
canonical bytes, OIDs, schemas, Refs, archives, and Human Decision boundary.
Two damage cases now report a different error code. See the upgrade notes.

## Changes since v1.4.0

### Added

- `synapse repair REPO --from PATH` puts damaged or missing objects back from a
  good copy: an export archive, a copy of the repository, or an original file.
  One damaged image used to stop every session page, `creator-report`,
  `creator-run`, and `export` for the whole repository. Only bytes that hash to
  the object's OID are used. Refs, the reflog, and intact objects do not change,
  no object is created, and damaged files move to `cas/quarantine/`.
  - An object with a Tombstone is not brought back. A Tombstone in a given copy
    also stops its target from coming back, but `repair` never adds a Record
    the repository does not name.
  - If a damaged Record has no copy, nothing is restored, because it could be
    such a Tombstone.
  - Without a good copy the object stays damaged, and a damaged `refs.sqlite3`
    still needs `restore`.

  See "Put a damaged record back" in the Creator workflow.

### Changed

- One integrity check reads and hashes each object once. On one machine with a
  2.1 GiB repository, opening a session page fell from 5.6 to 1.0 seconds and
  `creator-run` from 19.7 to 5.8 seconds. Every stored object and every Ref
  closure is still verified.
- A repository can hold 16 GiB of objects before `creator-run`, `inbox decide`,
  and the localhost import stop accepting new sessions, up from 4 GiB. The
  25,000 object limit is unchanged. A `resource_limit` error on the command
  line now says what to do next.
- The macOS arm64 archive is built and smoke-tested on macOS 15, because GitHub
  retired its macOS 14 runners on November 2, 2026.
- Updated `jsonschema` 0.58.2 → 0.60.2, `tokio` 1.53.1 → 1.54.1, `toml` 1.1.6 →
  1.1.8, and compatible transitive crates.

### Fixed

- A repository keeps working after a file manager opens its folders. Finder's
  `.DS_Store` and `._*` files and Explorer's `Thumbs.db` and `desktop.ini`
  inside `cas/objects/` previously made `fsck`, `creator-report`, `creator-run`,
  `export`, and the session pages fail with `schema_invalid: invalid store
  path`. A directory or symlink with one of these names is still an invalid
  path.
- `synapse init` and `synapse serve` accept a folder that holds only such files
  as empty, so a folder created in Finder can become a repository.
- `synapse fsck` lists all damage. A corrupt Record or an unknown file in the
  store ended the check at the first one, which hid every other issue. They are
  now reported as `issue:` lines like any other damage, and the localhost
  maintenance check finishes with a dirty result.
- `synapse fsck` no longer takes time proportional to Refs times Records.
- `synapse present preview` and `present export --replace` name the file when a
  bundle has an unlisted or missing file, such as a `.DS_Store` left by opening
  the bundle in Finder.

### Upgrade notes

- A corrupt Record now ends `synapse fsck`, `creator-report`, and `creator-run`
  with `fsck_failed` instead of `oid_mismatch`. An unknown file in the store
  ends `synapse fsck` with `fsck_failed` instead of `schema_invalid`, and it
  still ends `creator-report` with `schema_invalid`. Scripts that match the old
  codes for these cases need the new ones.
- A repository above 4 GiB cannot go back to an older version. A version before
  v1.5.0 refuses to report on it with `resource_limit` and leaves it unchanged.
  Keep the repository at or below 4 GiB if you may need to return to one.

## Install and verify

Download the archive and `SHA256SUMS` for this exact release. Verify the
checksum and GitHub build provenance before extracting. If either verification
fails, stop. Do not extract or install an unverified archive. Export important
repositories with the old binary before updating, and retain the old archive
until v1.5.0 verifies the data.

See the tag-fixed [installation guide](https://github.com/howlrs/synapsegit/blob/v1.5.0/docs/install.md),
[changelog](https://github.com/howlrs/synapsegit/blob/v1.5.0/CHANGELOG.md), and
[compatibility policy](https://github.com/howlrs/synapsegit/blob/v1.5.0/docs/compatibility.md).
