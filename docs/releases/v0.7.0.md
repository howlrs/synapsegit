# SynapseGit v0.7.0 — Stage 0 preview

`v0.7.0` is a preview release on top of `v0.6.0`. It adds authenticated
localhost archive export and restore APIs to `synapse-local`, backed by new
bounded Core archive-restore resource limits, and tightens the shared
resource budget used by localhost archive listing. The Core v0.1 protocol,
`sg-oid-v1`, directory archive format, and existing command surfaces are
otherwise unchanged. This remains a source-available evaluation release, not
a production or hosted service.

## Highlights

- localhost archive export API: authenticated `POST
  /api/v1/projects/{projectKey}/archive-exports` accepts only a
  server-rooted logical slug plus exact project confirmation, reserves a
  process-local maintenance job, and publishes through Core's bounded
  atomic no-replace directory export. The project capability is enabled
  only when `--archive-root` is configured; restore and archive browser
  controls remain unimplemented.
- localhost archive restore API: authenticated `POST
  /api/v1/projects/{projectKey}/archive-restores` accepts only a
  server-rooted archive slug, exact target-project confirmation, and an
  explicit empty-target confirmation. It runs as a process-local
  maintenance job with a server-fixed `ArchiveRestoreLimits` profile,
  rechecks target emptiness in Core, supports only the documented
  exact-subset retry, and publishes Refs/reflog last. Restore UI remains
  unimplemented.
- bounded Core archive restore APIs: `ArchiveRestoreLimits`,
  `Repository::restore_archive_with_limits`, and
  `Repository::restore_from_with_limits` bound the destination and
  manifest object inventories, aggregate object bytes, Ref/reflog payload,
  shared Tombstone scan, and cumulative validation work across distinct
  archived heads. Existing restore entry points use the documented local
  defaults (and retain a repository's configured Tombstone scan limit); no
  archive-format or OID change is introduced.
- localhost archive listing now shares one cumulative 100,000-object / 1
  TiB manifest-declared-byte inspection budget across all candidate
  archives in a request. Exceeding either ceiling fails the request closed
  with the existing `resource_limit` code; a late-invalid archive retains
  its reserved inventory so repeated failures cannot reuse the same
  allowance. Archive format, OIDs, and the successful response schema are
  unchanged.

## Install on Linux x86-64 GNU

The prebuilt archive is produced on Ubuntu 22.04 and requires glibc 2.34 or
newer. Other supported Unix-like hosts can build from the fixed tag with Rust
1.88 or newer.

```bash
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.7.0/synapsegit-v0.7.0-x86_64-unknown-linux-gnu.tar.gz
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.7.0/SHA256SUMS
sha256sum --check SHA256SUMS

gh attestation verify synapsegit-v0.7.0-x86_64-unknown-linux-gnu.tar.gz \
  --repo howlrs/synapsegit \
  --signer-workflow howlrs/synapsegit/.github/workflows/release.yml \
  --source-ref refs/tags/v0.7.0 \
  --deny-self-hosted-runners
```

Stop if either verification command fails. Do not extract or install an
unverified archive.

```bash
tar -xzf synapsegit-v0.7.0-x86_64-unknown-linux-gnu.tar.gz

mkdir -p "$HOME/.local/bin"
install -m 0755 synapsegit-v0.7.0-x86_64-unknown-linux-gnu/synapse "$HOME/.local/bin/synapse"
install -m 0755 synapsegit-v0.7.0-x86_64-unknown-linux-gnu/synapse-local "$HOME/.local/bin/synapse-local"
install -m 0755 synapsegit-v0.7.0-x86_64-unknown-linux-gnu/synapse-present "$HOME/.local/bin/synapse-present"
export PATH="$HOME/.local/bin:$PATH"

synapse --version
synapse-local --version
synapse-present --version
```

All three binaries should report `0.7.0`. See the
[installation guide](https://github.com/howlrs/synapsegit/blob/v0.7.0/docs/install.md)
for source installation and update precautions.

## Compatibility and migration

- Repositories created with v0.6.x require no planned format migration. Core
  v0.1 objects, `sg-oid-v1`, and directory archive semantics are unchanged.
- The new `POST /archive-exports` and `POST /archive-restores` routes are
  opt-in and additive: both require `--archive-root` to be configured and an
  authenticated request, and `synapse-local` started without
  `--archive-root` behaves as before. No existing route, flag, or response
  shape changed.
- The new `ArchiveRestoreLimits` bound only newly introduced entry points
  (`Repository::restore_archive_with_limits`,
  `Repository::restore_from_with_limits`); existing restore entry points
  keep their documented local defaults and configured Tombstone scan limit,
  so no existing restore caller's behavior changes.
- The shared archive-listing inspection budget applies per request across
  all candidate archives rather than per archive; a request naming enough
  archives to jointly exceed 100,000 objects or 1 TiB of manifest-declared
  bytes now fails closed with `resource_limit` where it previously might
  not have. No archive format, OID, or successful response schema changed.
- No public Rust API shape changed for existing callers in this release.

Stage 0 APIs and formats do not yet carry a stable compatibility promise.
Export important repositories with the old binary before updating so that a
known-good recovery copy remains available.

## Known limits

- Generic-artifact support remains source-library-only, unchanged since
  v0.4.0. There is no generic-artifact HTTP, CLI, browser, or remote
  publication surface.
- Archive export and restore are now reachable via authenticated localhost
  API only when `--archive-root` is configured; archive browser controls
  and end-to-end UI remain unimplemented.
- Credentials and approvals remain process-local. Recovery requires fresh
  authentication and authorization, and never reconstructs prior authority.
- Generic public bundles are unsigned local derived views, not proofs of
  authorship, truth, permission, completeness, or physical change.
- The existing browser and command surfaces remain image-workflow-oriented.
- The prebuilt artifact is Linux x86_64 GNU only. No crates.io, GHCR, Windows,
  macOS, or Linux ARM64 package is published.
