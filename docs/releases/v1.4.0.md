# SynapseGit v1.4.0

`v1.4.0` makes CLI help, errors, and reports easier to read, rejects input
files that could stall a command, and fixes two localhost review issues, while
preserving the frozen v1 Core formats, canonical bytes, OIDs, schemas, Refs,
archives, stable error codes, and Human Decision boundary.

## Changes since v1.3.0

### Changed

- The text output of `synapse creator-report`, and the text result of
  `creator-run` and `inbox decide`, no longer prints Rust's internal notation.
  A generation note is printed as `generation_note_tool`,
  `generation_note_model`, `generation_note_prompt`, and
  `generation_note_intent` lines; decision pins as a
  `decision_pins_private=<count>` line followed by one tab-separated line per
  pin; and a derived session's source as `reused_reference_source_*` lines.
  Values stay escaped. JSON output is unchanged (#187).
- `synapse fsck` prints each issue on stderr as one readable line that names
  the check that found it (`store path`, `object`, or `closure`). Closure
  validation errors from Ref updates and archive restores describe the issue
  the same way. Exit codes, error codes, and the stdout summary are unchanged.

### Fixed

- The localhost Inbox review allows only one selection, discard, or proposal
  request at a time, so rapid actions no longer replace the selected preview,
  leave staged files behind, or discard files while a proposal is created.
- Creator decision pins reject positional JSON arrays instead of reading array
  elements as object fields. Valid object-shaped pins keep their format.
- `--help` or `-h` after other arguments prints help and exits 0, for
  `synapse present export|preview` (#240) and for Core commands.
  Previously `synapse present export <repo> --help` and
  `synapse export <repo> --help` wrote into a new `./--help` directory, and
  `synapse restore <archive-dir> --help` restored a repository there. An
  option value such as `--rationale -h` is still recorded as given.
- Core CLI errors print the stable error code once instead of
  `schema_invalid: schema_invalid: ...`. A missing positional argument in
  `creator-run`, `inbox put`, `inbox decide`, or `update-ref` is named in the
  usage error.
- `put-blob`, `put-record`, `build-tree`, `commit`, `put-object`, and
  `--generation-note-file` read only a regular file. A FIFO no longer blocks
  the command, and a directory is reported by its own path.

### Upgrade notes

- Scripts that read the `creator-report` text lines named above, or the
  `fsck` issue lines, need the new names. Use `--format json` for creator
  reports and the exit code with `fsck_failed` for `fsck`; those are
  unchanged.
- A pipe passed as `/dev/stdin` or `<(...)`, and `/dev/null`, are now
  rejected as put-command and `--generation-note-file` inputs. Write such
  input to a file first.

## Install and verify

Download the archive and `SHA256SUMS` for this exact release. Verify the
checksum and GitHub build provenance before extracting. If either verification
fails, stop. Do not extract or install an unverified archive. Export important
repositories with the old binary before updating, and retain the old archive
until v1.4.0 verifies the data.

See the tag-fixed [installation guide](https://github.com/howlrs/synapsegit/blob/v1.4.0/docs/install.md),
[changelog](https://github.com/howlrs/synapsegit/blob/v1.4.0/CHANGELOG.md), and
[compatibility policy](https://github.com/howlrs/synapsegit/blob/v1.4.0/docs/compatibility.md).
