# SynapseGit v0.9.0 — Stage 0 preview

`v0.9.0` adds safer repository opening and new localhost Creator workflows on
top of `v0.8.1`. It remains a source-available evaluation release for one local
user, not a production or hosted service. The Core v0.1 object/OID profile and
directory archive format are unchanged. The localhost API gains additive draft
operations and response fields; it has no stable compatibility promise.

## Highlights

- Commands that operate on an existing repository, including `refs`, `fsck`,
  `export`, and `creator-report`, now reject missing or incomplete repository
  paths instead of silently creating a new layout. `synapse-local` still
  initializes an **existing empty directory**, but rejects a missing path or
  a nonempty nonrepository. Explicit creation remains available through
  `synapse init PATH` and `synapse creator-run`; `init` refuses a nonempty
  nonrepository. The existing-command rejection is a Stage 0 behavior change
  from v0.8.1.
- The localhost image comparison dialog overlays two images with matching
  decoded dimensions and lets the user adjust the upper image opacity from
  0% to 100%. It remains a manual view, without registration or difference
  analysis.
- A configured `--import-root PROJECT=INBOX` exposes a bounded, read-only
  script-output Inbox. The user previews a manifest-last candidate, confirms
  the retained image bytes, and starts a fresh Proposal with explicit Human
  review. The Inbox is disabled unless configured. No decision or source
  history is changed automatically.
- A verified interrupted Proposal or completed Defer can supply the three
  stored images to a **new** session for another review. The old session and
  its Human Decision remain fixed. The new session gets fresh authority and
  records a private, immutable source binding. Frozen publication v1 refuses
  these sessions because it cannot represent that reuse lineage.
- The project page puts creation and session discovery ahead of maintenance.
  It shows bounded, explicitly unverified summaries (up to 200), filters,
  and links to derived sessions; opening a session still performs the strict
  verification. A malformed session head cannot hide healthy rows.
- `synapse export REPOSITORY out` now accepts a bare relative destination and
  finishes after publishing the archive. Git history import, identity
  mapping, and GitHub remote publication have a documented design and remain
  future work.

## Install on Linux x86-64 GNU

The prebuilt archive is produced on Ubuntu 22.04 and requires glibc 2.34 or
newer. Other Unix-like hosts can build from the fixed tag with Rust 1.88 or
newer. The archive contains the same three binaries: `synapse`,
`synapse-local`, and `synapse-present`.

```bash
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.9.0/synapsegit-v0.9.0-x86_64-unknown-linux-gnu.tar.gz
curl -LO https://github.com/howlrs/synapsegit/releases/download/v0.9.0/SHA256SUMS
sha256sum --check SHA256SUMS

gh attestation verify synapsegit-v0.9.0-x86_64-unknown-linux-gnu.tar.gz \
  --repo howlrs/synapsegit \
  --signer-workflow howlrs/synapsegit/.github/workflows/release.yml \
  --source-ref refs/tags/v0.9.0 \
  --deny-self-hosted-runners
```

Stop if either verification fails. Do not extract or install an unverified
archive.

```bash
tar -xzf synapsegit-v0.9.0-x86_64-unknown-linux-gnu.tar.gz

mkdir -p "$HOME/.local/bin"
install -m 0755 synapsegit-v0.9.0-x86_64-unknown-linux-gnu/synapse "$HOME/.local/bin/synapse"
install -m 0755 synapsegit-v0.9.0-x86_64-unknown-linux-gnu/synapse-local "$HOME/.local/bin/synapse-local"
install -m 0755 synapsegit-v0.9.0-x86_64-unknown-linux-gnu/synapse-present "$HOME/.local/bin/synapse-present"
export PATH="$HOME/.local/bin:$PATH"

synapse --version
synapse-local --version
synapse-present --version
```

All three binaries should report `0.9.0`. See the
[installation guide](https://github.com/howlrs/synapsegit/blob/v0.9.0/docs/install.md)
for source installation and update precautions.

## Compatibility and migration

- Existing valid v0.8.x repositories need no planned format migration. Core
  v0.1 objects, `sg-oid-v1`, and directory archive semantics are unchanged.
- Before updating, export an important repository with the old binary and
  retain the verified recovery copy. For a new repository, use `synapse init
  PATH` or the create-intent `creator-run` command. The localhost app can also
  initialize an existing empty directory. Existing-repository commands no
  longer create a layout as a side effect.
- Older v0.8.1 binaries can restore and fsck an archive containing the new
  reuse-source binding, but their `creator-report` omits that binding and
  their publication command does not guarantee rejection of these sessions.
  Use v0.9.0 to inspect or publish histories containing interrupted/Defer
  reuse.
- The new Inbox and overlay are localhost-only. They do not add a hosted
  service or a fourth binary. Generic-artifact support remains source-library
  only, without generic-artifact HTTP, CLI, browser, or remote publication.

Stage 0 APIs and formats do not yet carry a stable compatibility promise.

## Known limits

- Pending Human review authority is retained only in the running localhost
  process. Interrupted/Defer reuse starts a new review; it does not resume
  the old one or change its decision.
- The session list is a bounded overview, not an integrity verdict. Use the
  detail page or `fsck` to verify a session.
- Publication accessibility checks cover static structure and browser
  baselines. Screen-reader evaluation remains manual; the documented frozen
  corpus long-string reflow exception remains unresolved.
- The prebuilt artifact is Linux x86_64 GNU only. No crates.io, GHCR, Windows,
  macOS, or Linux ARM64 package is published.
